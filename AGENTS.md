# AGENTS.md

Guidance for AI coding agents (Claude, Cursor, Copilot, Codex, others) working in this repository.

This file is the contract. If a rule below conflicts with a default agent behavior, this file wins.

## Identity rules

- Commits stay attributable to a single human author. Do not add `Co-Authored-By` footers.
- Do not write "generated by", "with assistance from", "written by AI", or similar phrases anywhere in code, comments, commit messages, or PR descriptions.
- Do not mention Claude, Copilot, Cursor, or the underlying model by name in any artifact you produce.

## Writing rules

- No em dashes (—). They are a strong AI tell. Use commas, parentheses, "and", or split the sentence. Hyphens (-) for compound words are fine.
- No emojis anywhere. Code, README, commits, PR descriptions.
- No marketing fluff. Avoid "blazing fast", "comprehensive", "production-ready" unless earned.
- Vary phrasing in commit messages. Do not start every commit with the same verb.
- Plain English subjects. No conventional-commits prefixes (`feat:`, `fix:`, `chore:`) unless the team adopts them later.
- Subject line under 72 chars.

## Code rules

- TypeScript: no `any`. Define types in `src/lib/types.ts` or a similar shared module.
- No `console.log` in production paths. Use a logger or remove after debugging.
- Files under 500 lines. Split larger files into focused modules.
- Comments only when the why is non-obvious. Do not narrate what the code does.
- Frontend styling: Tailwind only. No inline styles, no other CSS frameworks.
- Frontend icons: Lucide only.
- Backend Lambda: keep `handler.js` under 500 lines. Extract helpers as the file grows.

## Workflow rules

- Branch from `main`: `feat/<short-name>` or `fix/<short-name>`.
- One logical change per commit. No squashed mega-commits during development.
- Sign commits with SSH where possible. See `README.md` for setup.
- Open a PR, do not push directly to `main`.
- Do not force-push to shared branches.

## Hook expectations

The repo runs Husky hooks (educational by default, strict opt-in via `HUSKY_STRICT=1`):

- `pre-commit` formats staged files with Prettier. Fast.
- `commit-msg` warns on em dashes, AI mentions, Co-Authored-By footers, oversized subjects, and emojis. Warnings do not block unless `HUSKY_STRICT=1`.
- `pre-push` runs typecheck and build for whichever workspace you touched. Blocks on failure with the underlying error.

Read the hook output, fix issues in the next commit. Do not bypass with `--no-verify` unless you have a real reason and document it in the PR.

## What you should do at session start

1. Read this file.
2. Read the workspace `README.md` for setup and structure.
3. Check the open PRs and recent commits to understand the current state.
4. If unsure about the right approach for an AWS task, invoke the relevant AWS skill (Claude users: `aws-core:*` skills).
5. Plan multi-step work before writing code. Keep commits small and verifiable.

## What you should not do

- Do not commit secrets. Never put credentials in code, env example files, or commit messages.
- Do not connect to Marriott networks or APIs. This is a hackathon submission and Marriott infra is off limits per the codefest rules.
- Do not use real Marriott customer data. Test data lives in `seed_data/` and is synthetic.
- Do not delete or rewrite history on branches that have been pushed.

## Tech stack (already decided)

- Backend: Node.js 18 Lambda, Serverless Framework, DynamoDB PAY_PER_REQUEST.
- Frontend: Vite, React 18, TypeScript, Tailwind 3, React Router 6.
- Infra: AWS CDK v2 in TypeScript. Two stacks: `codefest-dynamodb`, `codefest-budgets`.
- Auth: HTTP Basic Auth at client level, app user creds in login body. Single static MFA OTP for the demo.

Do not introduce alternatives (no Vue, no raw CloudFormation YAML, no Pulumi, no Yarn, no Bun) without a written justification in the PR.

## Post-event upgrade path (not for hackathon)

Documented here so the next person knows where the team is heading after May 22, 2026:

- Replace Prettier with Biome for ~10x faster formatting and integrated linting (single tool, single config).
- Replace heuristic fraud logic in `apps/backend/src/handler.js` with a SageMaker Serverless Inference endpoint.
- Stream `UserActivity` writes through Kinesis Firehose to S3 for offline feature store.
- Replace the static MFA OTP with Amazon Cognito + SNS for real OTP delivery.
- Add CloudFront in front of API Gateway with AWS WAF rules for rate limiting on `/auth/login` and `/transactions/transfer`.

These are notes, not action items. Do not implement during the hackathon.
